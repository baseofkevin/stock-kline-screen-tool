# K 线选股工具

本仓库只做 K 线选股、前向评估与历史数据下载，不依赖 LLM，不输出买卖指令。
单股顶部观察已拆分为独立项目：`baseofkevin/stock-judge-top-tool`。

本文件同时是程序使用说明和选股规则说明：运行流程、规则口径、参数常量、数据源、输出字段、
指标实现细节、测试与已知局限都在这里，不再单独维护规则说明书。

| 程序 | 作用 | 主要输出 |
|---|---|---|
| `kline_screen.py` | 按 K 线规则做周频选股 | `csv_output/选股_<基准日>.csv` + `database/result_<基准日>.json` |
| `evaluation/download_history.py` | 批量下载历史横截面、标签、K 线、市值数据 | `database/` 下的原始数据 |
| `evaluation/evaluate.py` | 对历史名单做前向评估（5/10/20 日收益与超额） | 终端报表 + `evaluation/picks_log.csv` |

## 当前功能摘要

| 项 | 当前值 |
|---|---|
| 策略 | 最近 5 个交易日内，放量向上突破 MA20，且突破后未跌破 MA20 |
| 扫描周期 | K = 5 个交易日 |
| 新鲜度窗口 | N = 4（必须 = K − 1） |
| 启动日放量 | 成交量 ≥ 1.5 × 前 5 日均量 |
| 启动日涨幅 | 0.5% ~ 20.5% |
| 主力资金 | 仅展示：当日净流入、5 日净流入（v1.3 起不再参与筛选） |
| 换手分位 | 粗筛池内 20 日换手排名，默认**只排序标注**；`--turn-pct 0.4` 才硬过滤 |
| 均线结构 | MA20 ≥ MA60 × 0.95，且 MA20 近 3 日跌幅不超过 1% |
| 风控 | 非 ST、非次新（上市满 3 年）、非停牌、非退市 |
| 行业归属 | 申万一级/二级，**只展示**（v1.7 起），30 天缓存 |
| 业绩标注 | 仅「毛利率环比改善」一项（v1.9 删除订单增长、经营现金流、财务健康、PE/PB/PS） |
| 输出 | 16 列 CSV + 完整 result JSON + 逐股剔除明细 |
| 名单上限 | 无，全部纳入，不排序截断 |

程序版本 v1.10。

## 一次运行的完整流程

`pipeline.run()` 固定六步，输出只落在最后一步：

```text
[1/6] 交易日历        确定基准日 S、扫描窗口 need = 最近 K 个交易日
[2/6] 横截面粗筛      逐日调 screen condition，落盘 cross_<d>.json
[3/6] 标签排除        ST + 四个次新分桶，落盘 labels_<d>.json
[4/6] 日K线           候选并集，增量补新，落盘 kline_<起>_<止>.json
[5/6] 逐条裁决        find_start() 定位启动日 → judge() 逐条过规则
[6/6] 行情与标注      行情快照 → 换手分位 → ①毛利率改善 → 行业归属 → 写盘
```

各步骤的实现位置：

| 步骤 | 代码 | 关键点 |
|---|---|---|
| 1 准备 | `pipeline._prepare` | 校验 `--n ≥ 0`、涨幅区间、`--turn-pct ∈ [0,1]`；`S` 必须是交易日；**收盘前直接终止** |
| 2 粗筛 | `pipeline._load_cross` / `datasources.market.get_cross` | 表达式签名 `sha1("v3|"+expr)` 写进 `.meta.json`；缺字段直接报错 |
| 3 标签 | `pipeline._load_labels` | 标签接口失败抛 `RuntimeError`，不允许静默漏剔 |
| 4 K 线 | `datasources.kline.get_kline` | 20 只/批、批间自适应节流；以最新一份 `kline_*.json` 为底稿只补新增 |
| 5 裁决 | `selection._select` → `rules.find_start/judge` | 每只股票有且只有一种去向：入选或某个阶段被剔 |
| 6 标注 | `selection._enrich_market` → `annotate.*` → `_write` | CSV 原子写 + 行数校验，不一致则不写 result JSON |

流程末尾有三条硬断言（不满足直接抛错，不产出不可信名单）：

```text
粗筛池 == 入选 + Σ剔除
剔除代码 ∪ 名单 == 粗筛池
CSV 行数 == 名单数量
```

## 运行前提：基准日必须已收盘定稿

选股的三个核心口径只在收盘后成立 —— 日 K 的**收盘价**（`find_start` 的真突破判定）、
当日**成交量**（量能倍数）、当日**成交额**（20 日换手% 的分子）。因此 `pipeline._prepare`
在确定基准日 S 之后会先做一次定稿校验：

```text
S 早于今天                     → 放行
S == 今天 且 now ≥ 15:05       → 放行
S == 今天 且 now <  15:05      → 立即终止（不发任何取数请求）
```

盘中被终止时只花不到 1 秒：

```text
[1/6] 交易日历 ...
错误：基准日 2026-11-10 尚未收盘定稿（当前 2026-11-10 10:24，需 15:05 之后）。
      盘中运行时收盘价、量能倍数、换手%都还不完整，此时选股得到的名单不可信，因此直接终止。
      请收盘后重跑，或改用 --date 2026-11-09。
```

### 为什么必须拒绝，而不是「先跑着看」

服务端在开盘前和盘中**照样会返回一份「当天」的粗筛名单**，看上去一切正常：

| 时刻 | 实际发生了什么 |
|---|---|
| 09:04 | `screen condition --date 当天` 返回 1527 只「当天有成交」的票（实为盘中/前一日快照） |
| 09:13 | 一只股票的当天日 K 都还没生成 → `require_codes` 的收尾校验抛 `RuntimeError` |
| 09:30 | 开盘 |
| 10:10 | 服务端已有当天 bar（`kline sh600000 --start 当天` 返回 last 10.07），缓存里却是空的 |

更麻烦的是那份快照会被写进 `cross_<day>.json` 并带上**匹配的缓存签名**，等收盘后重跑时
被当成定稿数据直接复用 —— 池子是按盘中（甚至前一日）的涨幅选的，一句提示都没有。
2026-11-10 实测：缓存里 `sz301718` 的 `ClosePrice=57.48`，服务端对同一天返回 `56.48`。

### 缓存怎么知道自己是不是「收盘前抓的」

`common/session.py` 提供两级判断：

1. **meta 里记 `final`**：`cross_<day>.meta.json` 与 `kline_<起>_<止>.meta.json` 都会写入
   `final` / `end` / `saved_at`；读到非定稿缓存就重拉，并打印一行
   `[缓存失效] 2026-11-09：缓存在收盘前抓取（盘中快照），重新拉取`。
2. **旧缓存按写入时间兜底**：没有 `final` 字段的历史缓存，用文件 mtime 判断 ——
   「写入日 == 数据日 且 写入时刻 < 15:05」即视为盘中快照。这样既能纠正 2026-11-09 /
   2026-11-10 这两份中毒缓存，又不会让几百份历史 cross 缓存全部失效。

覆盖范围与各自的理由：

| 缓存 | 是否校验 | 理由 |
|---|---|---|
| `cross_<day>.json` | 是 | 粗筛池由当日涨幅选出，盘中值会选错整池股票 |
| `mv_<day>.json` | 是 | 换手% 的分母，盘中市值未定 |
| `quote_<day>.json` | 是 | CSV 的「最新收盘价」列 |
| `kline_<起>_<止>.json` | 是 | 底稿尾部那根半成品 bar 会被「已更新」判定永久保留 |
| `labels_<day>.json` | 否 | ST / 次新是日级属性，盘中盘后一致；少一次重拉少一分限频风险 |

## 策略逻辑

核心是把「启动事件」定义清楚：

> **当天上穿 MA20 且当天放量**，而不是「站上 MA20」这个可以连续成立几十天的状态。

因此规则从扫描日 S 往回找启动日 d\*：

- d\* 必须是真上穿：前一日收盘 ≤ MA20，当日收盘 > MA20；
- d\* 必须放量：当日成交量 ≥ 前 5 日均量的 1.5 倍；
- d\* 当日主力净流入与 5 日净流入只作展示，不作为启动条件（v1.3 起）；
- d\* 必须满足均线结构；
- d\* 到 S 之间不能跌破 MA20；
- 距启动日不能超过 N 个交易日。

### 启动日是怎么找到的（`find_start()`）

```python
i = S 在该股 K 线中的下标
if i < MIN_HISTORY(70): 剔除        # 不足约 71 根，算不了 MA60 也没回扫余量

# 从 S 往前连续统计「收盘 > MA20」的天数 up（MA 为简单均线，含当日）
for j 从 i 回扫到索引 20（回扫上限）:
    if 收盘[j] > MA20(j): up += 1
    else: break

d* = i - (up - 1)                   # 连续站上段的起点

# 真上穿断言：d* 前一天必须不站在 MA20 上
if 收盘[d*-1] > MA20(d*-1): 剔除    # 「连续站上 MA20 超过回扫上限」

vcross = 成交量(d*) ÷ 前 5 个交易日（不含当日）均量
```

这样定义的好处：**「启动」是一个事件，而不是一个可以连续成立几十天的状态**。
若股票回踩跌破 MA20 后再次上穿，新上穿日会被记为新的 d\*，视为一次新启动。

## 完整规则

### 启动日 d\* 的条件

| # | 条件 | 当前口径 |
|:--:|---|---|
| ① | 向上穿越 MA20 | `收盘(d*−1) ≤ MA20(d*−1)` 且 `收盘(d*) > MA20(d*)` |
| ② | 上穿日放量 | `成交量(d*) ≥ 1.5 × 前5个交易日成交量均值`（不含当日） |
| ③ | 日频条件 | 当日涨幅 `0.5% ~ 20.5%`（主力净流入仅展示，不筛选） |
| ④ | 均线结构 | `MA20 ≥ MA60 × 0.95`；`MA20(d*) > MA20(d*−3) × 0.99`（近 3 日跌幅不超过 1%） |
| ⑤ | 风控 | 非 ST、非次新（上市满 3 年）、非停牌、非退市；d\* 与 S 各检查一次 |

补充说明：

- **① 的本地断言**：`find_start()` 的回扫上限是索引 20。若股票连续站上 MA20 超过这个上限，返回「非真上穿（连续站上 MA20 超过回扫上限）」，不会返回虚假启动日。
- **③ 的字段请求**：粗筛表达式中的 `MainNetFlow > -1000000000000000` 与 `MainNetFlow5D > -1000000000000000` 是**恒真条件**，唯一作用是让服务端返回这两列。不能删除；删掉后本地读不到字段，程序会报错（若连字段防线一起删，名单会被静默清空）。详见[数据陷阱](#数据陷阱)。
- **⑤ 的次新判定**：用服务端 `listeddate_5days / listeddate_3mons / listeddate_1year / listeddate_3year` 四个标签桶的并集，等价于「上市不满 3 年」；没有本地 `LISTED_YEARS` 常量。

### 扫描日 S 的条件

| # | 条件 | 当前口径 |
|:--:|---|---|
| ⑥ | 启动后未破坏 | 自 d\*+1 到 S，每个交易日收盘价始终 `> MA20` |
| ⑦ | 新鲜度 | `S − d* ≤ 4` 个交易日（默认 N=4） |

⑥ 是**定义性条件**，不是独立过滤关：

- `find_start()` 从 S 往回走，收盘价跌破 MA20 即停止，所以 d\* 按定义就是「到 S 为止未被破坏的那一段」的起点。
- 代码保留⑥的循环作为防御性断言，正常数据下剔除数为 0。
- 若股票回踩跌破后再次上穿，规则会把新的上穿日记为 d\*，视为一次新启动，而不是判旧启动失败。

### 规则在代码中的落点

| 环节 | 函数 / 常量 | 说明 |
|---|---|---|
| 定位启动日 | `rules.find_start()` | K 线索引 ≥ `MIN_HISTORY=70`；回扫上限为索引 20；同时算出 `age`、`vcross`、MA20/MA60 |
| 逐条裁决 | `rules.judge()` | 按顺序检查 ⑦ 新鲜度 → ② 放量 → ③ 涨幅/风控 → ④ 均线结构 → ⑤ ST/次新 → ⑥ 未破 MA20 |
| 放量倍数 | `K_VOL=1.5` | `vcross < k_vol` 即剔除；`vcross` 用原始成交量比值，不受「股/手」单位影响 |
| 涨幅区间 | `CHG_LO=0.5`、`CHG_HI=20.5` | 用服务端原始 `ChangePCT` 本地复检（±1e-9 容差），不盲信服务端筛选 |
| 均线结构 | `C3_RATIO=0.95`、`C2_TOL=0.01` | `MA20 ≥ MA60×0.95`；`MA20(d*) > MA20(d*−3)×0.99` |
| 距 MA60 上限 | `MA60_GAP=0.0` | 默认 0 = 关闭；`--ma60-gap` 才启用 |
| 换手过滤 | `metrics.turnover.apply_turnover()` | 默认 `TURN_PCT=0.0` 只排序；硬过滤时按 `TURN_MIN_N=5` / `TURN_MAX_N=30` 自适应 |
| 剔除原因归一 | `rules.reason_cat()` | 数字替换为 `#`（保留 `MA20/MA60` 可读），用于顶层统计；原文与逐股映射另存 |

### 排序与数量

- 不设名单上限，也不按涨幅或量能截断。
- v1.2 起名单按「池内 20 日换手分位升序」排列：最冷的排前面，方便从低关注度的一端开始人工审核。
  这只是展示顺序，不改名单构成；分位为「-」的（数据不足）排在最后。
- 需要剔除高换手时，用 `--turn-pct 0.4` 打开硬过滤。

### 换手分位（v1.2）

| 项 | 口径 |
|---|---|
| 指标 | 最近 20 个交易日的日均成交额 ÷ 流通市值（%） |
| 比较范围 | **当天粗筛池**（当日通过涨幅/资金条件的全部股票），不是全市场、也不是最终名单 |
| 默认（`--turn-pct 0`） | **只排序标注**：名单不变，按分位升序展示 |
| 硬过滤（`--turn-pct 0.4`） | 只留分位最低 40%（Q1–Q2） |
| 自动放宽（硬过滤时） | 按 40% 过滤后不足 5 只 → 放宽到最低 60%（Q1–Q3） |
| 自动收紧（硬过滤时） | 超过 30 只 → 收紧到最低 20%（Q1）；若 20% 档会清空则保持 40% |
| 数据不足 | 20 个交易日内有效数据 <15 天 → 标注「换手数据不足」并保留，不剔除 |
| 池内样本 | 可算换手的池内股票 <20 只 → 分位不稳定，本次跳过硬过滤（仍标注） |

为什么用「池内分位」而不是固定阈值：全市场换手水平随行情冷热漂移，固定 3% 在火热期会留下
一堆更热的票、在冷清期会全部剔除。分位口径能自适应，且与顶部观察项目（`stock-judge-top-tool`）里「换手率自身分位」
是两回事——这里比的是**同一天不同股票之间**的拥挤度。

为什么默认只排序、不剔除：本样本内换手分位的解释力远大于「上穿+放量」本身——控制住换手
之后，入选股相对「同日同换手五分位」的超额只有 −0.3%（n=481）。也就是说超额主要来自
「往低换手一侧挪」这个动作，而不是核心信号。硬过滤会让工具名实不符（叫「放量上穿」，
赚的却是低换手因子），且低换手因子的有效性高度依赖小盘/题材周期。因此默认把它降级为
排序信息，需要时再显式打开。

为什么高换手要警惕：异常换手在 A 股是稳定的负向因子（RoF 2016；LSY 2019 把异常换手作为情绪因子）。
本样本内粗筛池按 20 日换手五等分，20 日超额从 Q1 的 +4.4% 单调降到 Q5 的 −6.1%。

成交量单位：科创板（`sh688`）接口返回的 `volume` 是「股」，其余板块是「手」；程序统一换算成
「股」后再算成交额，K 线带 `amount` 字段时直接用金额。

计算明细（`metrics/turnover.py`）：

- **20 日换手%** = 近 20 个交易日成交额的均值 ÷ 流通市值 × 100；成交额优先取 K 线 `amount`（元），
  缺失时用 `close × volume` 估算。
- **分母**取 d\* 里最近一天的 `NegotiableMV`（元），不是 S 日——20 日均值对几天市值漂移不敏感，
  这样不必为 S 日再发一次网络请求。
- **池内分位** = 池内严格小于该股换手的只数 ÷ 池内可算总数 × 100（0 = 最冷，100 = 最热）；
  同值股票分位相同，不是排名次。
- **星级**：分位 <20 → `***`、<40 → `**`、<60 → `*`、其余留空（边界 20 归 Q2、40 归 Q3）。
- **数据不足**：窗口内有效天数 <15 → 记「换手数据不足」并保留；池内可算样本 <20 只 → 本次跳过硬过滤（仍标注）。
- **硬过滤取整**：剔除线取 `vals[int(m × pct)]`，是池内实际换手值，不是插值分位。

### 运行时间

一次完整扫描大致包含：

- 交易日历 1 次；
- 横截面粗筛约 5 次；
- 标签约 25 次；
- K 线：**日常增量约 85 批**（每只只补上次之后新增的 1~5 根，60 只/批）；
  首次全量约 250 批（20 只/批）；
- 行情 1 批；
- 入选股的业绩转变财务取数。

整体耗时（2026-11 实测/按实测外推）：

| 场景 | 第 4 步（取 K 线）耗时 |
|---|---|
| 当日已跑过、缓存命中 | 实测 16 秒（只重写一次盘） |
| 换基准日（日常增量） | 约 1.5~2 分钟 |
| 首次全量（无历史底稿 / `--refresh`） | 约 7~8 分钟 |

K 线是整轮最慢的一步：服务端有频控（约 600~700 只/分钟），20 只/批、批间自适应
节流；`database/kline_*.json` 之间的历史会被复用，所以只有第一次是全量。
建议在收盘后（16:00 左右）运行，保证横截面和 K 线都是当日收盘口径。

## 参数

| 参数 | 当前值 | 说明 |
|---|---|---|
| 扫描周期 K | 5 个交易日 | 每周一次；覆盖率与执行频率的折中 |
| 新鲜度窗口 N | 4 | 必须等于 K−1；窗口过大只会增加重复推送 |
| 启动日放量 K_VOL | 1.5× | 介于「倍量」与不过度缩小池子之间 |
| 涨幅区间 | 0.5% ~ 20.5% | 覆盖主板 10% 与创业板/科创板 20% 涨停；北交所出现时需另行调整上限 |
| 换手分位 | 只排序、不剔除 | 20 日换手分位仅影响展示顺序；`--turn-pct 0.4` 才硬过滤 |
| MA20/MA60 比值 | 0.95 | 允许 MA20 低于 MA60 最多 5%（v1.4 由 0.98 放宽，覆盖均线修复初期） |
| MA20 近 3 日容忍度 | 1% | 刚上穿时 MA20 可能仍在走平或下行，完全不许下行会误杀 |
| 距 MA60 上限 | 0（关闭） | 可通过 `--ma60-gap` 开启；当前默认不限制 |
| 上市时长 | 满 3 年 | 次新股价格与均线结构不稳定，且缺少足够年报 |

参数选择基于覆盖率、名单规模、阈值敏感性，不以历史收益率为优化目标。

## 数据源

全部来自腾讯自选股官方接口（`westock`），不引入第三方数据。

| 用途 | 命令 | 说明 |
|---|---|---|
| 横截面粗筛 | `westock screen condition` | 服务端过滤涨幅、退市、停牌；净流入字段仅请求返回，不筛选 |
| 排除集 | `westock screen label` | ST + 四个次新分桶 |
| 日 K 线 | `westock kline` | 串行 20 只/批；该 CLI 有本机限频器，不能并发 |
| 行情 | `westock quote --date <基准日>` | 收盘价、流通市值、换手；必须传 `--date` |
| 财务 | `westock data_finance` | 利润表、财务比率，仅用于「毛利率环比改善」标注 |
| 行业 | `westock data_sector` | 申万一级/二级行业成分股，用于行业归属标注 |

### 数据陷阱

#### 陷阱 1：`MainInflowCircRate` 的符号被丢弃

该字段实测只返回绝对值，无法区分净流入/净流出。

程序**不使用该字段**，改为本地计算：

```text
市值比% = 当日主力净流入(元) ÷ 流通市值(元) × 100
```

> v1.1 起市值比**只作展示列**，不再作为入选条件（审核发现该条件相对粗筛池的超额为负）。

#### 陷阱 2：`quote` 的市值单位随 `--date` 变化

| 调用 | `circulating_market_cap` | 单位 |
|---|---|---|
| `quote sh600333` | `40.26` | 亿元 |
| `quote sh600333 --date 2026-10-14` | `4263000000` | 元 |

程序按数量级统一归一化为「元」。

#### 陷阱 3：粗筛只返回表达式引用到的列

返回表里有哪些列，取决于 `CROSS_TPL` 引用了哪些字段。没被引用到的列不会出现。

例如删掉 `MainNetFlow > -1000000000000000` 后，返回行里不再有 `MainNetFlow` 字段，本地市值比全部算不出来，程序会报错；若同时删掉字段防线，名单会被静默清空。

因此：

- `MainNetFlow > -1000000000000000` 在表达式里是**恒真条件**，只承担「字段请求」职责（v1.3 起不再筛选净流入）；
- 任何字段（`ChangePCT`、`MainNetFlow5D` 等）一旦不再被引用，都会从返回里消失；
- 改动 `CROSS_TPL` 后必须重跑验证，并同步提升 `CROSS_CACHE_VERSION`，避免旧缓存被误用。

## 输出

### `csv_output/选股_<基准日>.csv`

UTF-8 with BOM，Excel 友好。当前固定 **16 列**。v1.8 删除「订单增长」与 DCF 三列；
v1.9 再删除「经营现金流情况」「财务健康提示」「PE」「PB」「PS」五列，
v1.10 在末尾新增「总市值（亿）」列。历史 CSV 不自动回写：

| 列 | 含义 |
|---|---|
| 代码 | 股票代码 |
| 名称 | 股票名称 |
| 一级行业 | 申万一级行业（31 个），如「电力设备」；无归属时记「未分类」 |
| 二级行业 | 申万二级行业（124 个），如「光伏设备」；无归属时记「未分类」 |
| 启动日 | d\*，向上穿越 MA20 且放量的那一天 |
| 距启动交易日 | S − d\*，取值 0~4 |
| 启动日量能倍数 | 成交量(d\*) ÷ 前 5 日均量 |
| 启动日涨幅% | 当日涨幅 |
| 距MA20% | 收盘价相对 MA20 的位置 |
| 距MA60% | 收盘价相对 MA60 的位置 |
| 毛利率改善 | `是 / 否 / 无数据 / 不适用` + 证据 |
| 20日换手% | 最近 20 个交易日日均成交额 ÷ 流通市值 |
| 池内换手分位 | 该股在当天粗筛池中的换手分位（0 = 最低，100 = 最高；空 = 数据不足） |
| 分位星级 | Q1（0–20）→ `***`，Q2（20–40）→ `**`，Q3（40–60）→ `*`；Q4/Q5 或分位为空留空 |
| 最新收盘价 | 基准日收盘价（元），与 K 线末根收盘一致 |

「毛利率改善」**只标注，不参与筛选、排序或裁决**；换手两列是 v1.1 过滤的依据，
同时留作复核参考（分位高但被保留的，通常是数据不足或名单过少时的兜底）。
「分位星级」只是分位的速读标记，不改变名单、不参与排序或裁决。

**总市值列（v1.10）同样只展示，不参与筛选、排序或裁决。** 口径：

- 与市值比、换手同用 d\* 日的市值快照（`mv_<d*>.json` 的第 2 个值），
  不为基准日 S 再发请求；市值取自收盘后快照，与盘中价对应的市值略有出入。
- mv 文件已核对全市场条目均为 `[流通市值, 总市值]`（元）；
  极端情况下总市值缺失时该列留空，不中断选股。

**行业两列（v1.7）同样只展示，不参与筛选、排序或裁决。** 口径与维护方式：

- 来源：westock `data_sector` 的申万行业成分股（一级 31 个 + 二级 124 个），
  不是东财/同花顺的自定义板块，也不是概念板块；同一只股票取官方申万归属。
- 缓存：落盘 `database/industry_map.json`，30 天有效；平时零请求，
  过期或加 `--refresh-industry` 才重建（约 150 次请求 / 2~3 分钟）。
  重建失败时沿用过期缓存，没有缓存则整列记「未分类」，**绝不中断选股**。
- 覆盖：A 股 5578 只有一级归属、5556 只有二级归属；缺的多为新股、退市整理
  或尚未纳入申万分类的标的，记「未分类」而不是猜一个。
- 回填：历史 CSV 不会自动改；v1.7 只对重跑的期次生效（最新一期已手工回填）。
- 用途：一眼看出名单是否押在单一行业（例如 155 只里 17 只传媒），
  便于后续按行业做分散或做行业中性评估。

## 使用方式

### 周频选股

```bash
# 默认扫描最近交易日，K=5
python3 kline_screen.py

# 指定基准日
python3 kline_screen.py --date 2026-10-14

# 强制重新下载原始数据
python3 kline_screen.py --refresh

# 换扫描周期（N 必须 = K−1）
python3 kline_screen.py --n 2     # 每 3 个交易日
python3 kline_screen.py --n 0     # 每个交易日
```

主要参数：

| 参数 | 说明 |
|---|---|
| `--date` | 基准交易日，默认最近交易日 |
| `--n` | 新鲜度窗口，必须等于扫描周期减 1；默认 `4` |
| `--k-vol` | 启动日放量倍数，默认 `1.5` |
| `--chg-lo` / `--chg-hi` | 启动日涨幅区间，默认 `0.5` ~ `20.5` |
| `--turn-pct` | 换手硬过滤保留池内最低比例：默认 `0`（只排序标注），`0.4`=只留 Q1–Q2 |
| `--turn-min` | 名单少于该数时自动放宽一档，默认 `5` |
| `--turn-max` | 名单多于该数时自动收紧一档，默认 `30` |
| `--ma60-gap` | 启动日距 MA60 上限，`0` 表示关闭 |
| `--refresh` | 忽略已有缓存，重新下载原始数据 |
| `--refresh-industry` | 强制重建申万行业归属表（默认 30 天缓存，重建约 2~3 分钟） |

### 前向评估（evaluation/evaluate.py）

```bash
python3 evaluation/evaluate.py                 # 评估全部 result_*.json，并更新 evaluation/picks_log.csv
python3 evaluation/evaluate.py --fetch         # 先补齐全市场日线再评估（需联网，约 20–60 分钟）
python3 evaluation/evaluate.py --no-log        # 只看报表
python3 evaluation/evaluate.py --json out.json # 另存结构化结果
```

- 收益口径：`收盘(S+h) / 收盘(S) − 1`；要求 S 与 S+h 当天都有成交价，停牌记「数据不足」，
  不用之前最近一根顶替（否则 3 天的涨幅会被标成 10 日收益）。
- 基准：等权全市场、同规模桶（流通市值五分位）、当期粗筛池；后两者对「小盘/风格」更公平。
  同规模桶要求桶内 ≥30 只有有效收益，当期粗筛池要求 ≥20 只；基准覆盖不足时该列整体置空，不用部分样本硬算。
- 涨停标注：北交所 30%、科创板/创业板 20%、主板 10%；涨幅 ≥ 涨停−0.3pct 记「是」，
  ≥ 涨停−2.5pct 记「接近」，其余「否」——用于复盘「启动日是否已涨停」。
- 覆盖门槛：某期某周期若全市场只有不到 500 只有成交价，该列不计算并提示补数据。
- 输出：终端报表 + `evaluation/picks_log.csv`（`日期,代码,名称,启动日,距启动,20日换手%,池内分位,启动日涨停,
  持有5/10/20日%,超额5/10/20日%,人工结论,理由`）。程序只维护自己的列，`人工结论/理由` 不会被动。
- 数据来源：只读 `database/kline_*.json` 与 `mv_*.json`；`--fetch` 调 `evaluation/download_history.download_kline`
  补齐 `[最早基准日, 最近交易日]` 的全市场日线，已下过的文件会复用。
- 完全离线；只有加 `--fetch` 才会联网补全市场日线。

### 历史数据下载（evaluation/download_history.py）

## 业绩转变（仅标注，不参与裁决）

K 线规则回答「什么时候启动」，业绩转变回答「有没有出现毛利拐点」。两者独立。

v1.9 起只保留 **① 毛利率环比改善** 一项：② 合同负债/订单增长 与 ③ 经营现金流
因计算结果参考意义不大（订单代理是近似值、OCF 受单季与并表口径影响），已连同代码一并删除。
CSV 只展示「毛利率改善」一列。

| # | 指标 | 口径 | 判定 |
|:--:|---|---|---|
| ① | 毛利率环比改善 | 最近两个单季毛利率严格递增；最新一季营收环比不为负；最新单季毛利率高于上年同季 | 三条同时成立 → 是；否则否；数据不足 → 无数据 |

取值：

| 取值 | 含义 |
|---|---|
| `是` | 该项成立 |
| `否` | 数据足够且明确不成立 |
| `无数据` | 所需字段缺失或不可比 |
| `不适用` | 银行、保险、券商等没有毛利率语义 |
| 空 | 财务数据整体获取失败，与「否」「无数据」不同 |

关键口径：

- 优先用 `GrossIncomeRatio_Q`；缺失时用利润表累计营收/成本差分还原单季值（Q1 不差分）。
  单季营收同理：优先 `OperatingRevenue_Q`，缺失用累计营收差分。
- 三重护栏：环比递增、营收环比不为负、同比高于上年同季，避免把季节性改善当成拐点（`TURN_GM_REQUIRE_YOY=True`）。
- 报表按 `InfoPublDate ≤ 基准日` 过滤，避免未来函数。
- 只对最终入选股取数，不增加全市场扫描；取数用财务比率表（`balancesheet`）与利润表，不再拉资产负债表。
- 基准报告期优先取财务比率表的最新一期（`_Q` 字段齐全），缺失时退回利润表。

实现要点（`metrics/turnaround.py`）：

```text
gm[dt] = GrossIncomeRatio_Q                        # 主口径
       或 (单季营收 − 单季成本) ÷ 单季营收 × 100     # 累计差分兜底

① = 毛利率递增(gm[q2] < gm[t])
    且 营收环比不为负(revq[t] ≥ revq[q2])
    且 毛利率高于上年同季(gm[t] > gm[去年同季])

p1_label: 三条全过 → 是；任一明确不过 → 否；字段缺失/不可比 → 无数据；
          金融股（EnterpriseType ≠ 一般企业）→ 不适用
```

## 实现细节（读代码 / 改代码时容易踩的点）

1. **`age` 是 K 线索引差，不是交易日差。** 停牌股的 `age` 会偏小，可能先被「新鲜度」判掉；
   程序会给出「启动日不在本次覆盖窗口（该股存在停牌）」这类专用原因，见已知局限 5。
2. **换手分子是成交额，不是股数。** K 线有 `amount` 字段时直接用；旧缓存没有该字段时走
   `close × volume` 估算，科创板 volume 已是「股」、其余是「手」。
3. **分位是「严格小于的比例」，不是排名。** 同值股票分位相同；分位为空（数据不足）的股票永远保留。
4. **变量名 `rat` 装的其实是资产负债表（`balancesheet`）报表行**，只因接口 `type` 叫 balancesheet；
   读代码时不要误以为是「财务比率」。
5. **v1.9 起财务只取「利润表 + 财务比率表」**，不再请求 `balance`；`database/finance_bal_*.json`
   是历史遗留文件，不再生成，可以手工删除。
6. **市值单位要归一。** `quote` 不带 `--date` 返回亿元、带 `--date` 返回元，程序按数量级
   `cap_to_yuan()` 统一成元；`total_market_cap` 只用于行情字段防线，
   CSV 的「总市值（亿）」来自 `mv_<d*>.json`（v1.10 起），不走 quote。
7. **`--refresh` 是全量重下**（横截面、标签、K 线、行情、财报），很慢；只重建行业表用
   `--refresh-industry`，两者不要混用。
8. **`evaluation/evaluate.py` 是独立程序**，只读历史 `result_*.json` 与 K 线/市值底稿，
   不参与选股主流程，也不会写 CSV。
9. **限频不会静默变成漏股：批内二分 → 轮间退避 → 行情核对，三道门。**
   - **批内二分**（`_kline_fetch`）：一批 60 只只回 10 只时，当场把缺的 50 只拆成
     25+25（不够再拆 10+10）重发，最多 `KLINE_SPLIT_DEPTH=3` 层。限频压的是「单次返回
     条数」，拆小就能拿全 —— 不需要等，平均 7 次请求补齐 60 只。
   - **轮间退避**：收尾对**所有**末日 ≠ `S` 的票补取 `KLINE_STALE_ROUNDS=5` 轮，
     只在「本轮还有进展」时继续，轮间退避 5 / 10 / 20 / 40 秒。
   - **行情核对兜底**（`_traded_on`）：跑完仍有陈旧票时，用 `quote --date S` 逐只核对
     当日成交量 —— **有成交 = 限频漏取，直接报错不出名单**；无成交 = 真停牌，告警后按
     「无当日数据」剔除；核对不到的会单独点名，绝不假装成停牌。
   - 2026-11-10 的教训：原先只重试「当日在粗筛池」的票，池外 210 只明明有当日 K 线
     却被当停牌剔除，名单少了 2 只，而且一句提示都没有。

## 已知局限

1. **核心前提没有收益层面的实证。** 规则假设「放量上穿 MA20」能筛出值得研究的股票；这是概念推理，不是收益保证。
2. **参数多为结构选择。** 参数依据是覆盖率、池子规模、阈值敏感性，不是收益率优化。
3. **样本期有限。** 历史统计集中在特定市场阶段，不能代表所有牛熊状态。
4. **名单规模波动大。** 普涨周名单会明显变长；不设上限是有意为之。
5. **窗口内停牌会让 d\* 落到覆盖窗口之外。** `age` 是该股 K 线索引差，不是市场交易日差；程序会给出「启动日不在本次覆盖窗口（该股存在停牌）」的专用原因。
6. **北交所口径需注意。** 当前涨幅上限 20.5% 覆盖主板 10% 与创业板/科创板 20%；若粗筛池出现 `bj*`，程序会在 stderr 告警，应改用 `--chg-hi 30.5`。
7. **不构成投资建议。** 名单只是候选研究池，买卖决策需自行完成。

## 常见问题

### 为什么提示「基准日 … 尚未收盘定稿」？

在 15:05 之前运行、且基准日就是今天时会出现。原因见
[运行前提](#运行前提基准日必须已收盘定稿)：此时日 K 的收盘价、当日成交量、当日成交额
都还没定，服务端却仍会返回一份「当天」的粗筛名单。要么等收盘后重跑，要么指定上一个
交易日：

```bash
python3 kline_screen.py --date 2026-11-09
```

如果已经误在盘中跑过，也不用手工删缓存 —— 下次运行会打印
`[缓存失效] …：缓存在收盘前抓取（盘中快照），重新拉取` 并自动重拉。

### 跑完提示「K 线末日≠…」怎么办？

先看数量。正常应接近 0（只剩停牌股）。工具本身已经做了**批内二分 + 5 轮退避**，
如果还剩几十上百只，说明正好撞上较长的限频窗口 —— 隔几分钟重跑即可：已抓到的会增量
复用，不会从头再来，通常第二次几十秒就补齐。

若重跑后报 **「K线漏取（非停牌）」**，说明这些票当日确实有成交、却始终拿不到 K 线。
这是工具在**宁可失败也不产出缺股名单**：必须重跑，不能拿这份结果当准。
只有当告警写着「经行情核对当日无成交（停牌）」时，才表示剔除是合理的。

### 为什么「距启动」会有 0~4 天差异？

周频扫描覆盖最近 5 个交易日。股票周一启动、周五仍未跌破 MA20，就会以「距启动 4」出现在周五名单里。

### 同一只股票会连续几次出现吗？

默认 N=K−1，各次扫描的覆盖区间不重叠，正常不会重复；除非它启动→回落→再次启动。

### 为什么不做行业分散度约束？

候选池行业分散度本身较好；规则定位是「候选池」，不是组合构建。

### 为什么不设名单上限？

不设硬上限；默认名单规模就是通过核心信号的全部股票（本样本每周约 7 只）。名单偏多时可把
`--turn-pct` 调到 `0.4`（或 `0.2`）做硬过滤；偏少时保持默认即可。

### 为什么业绩转变只保留一项？

v1.9 起只保留「毛利率环比改善」。② 订单增长用的是「合同负债+预收款项」代理，
与真实在手订单差距大；③ 经营现金流用 TTM 口径，受并表范围与单季波动影响，
在样本内都被判定为参考意义不足，因此连同代码一并删除，避免输出看起来精确、
实际不可靠的判断。

## 数据与边界

- 所有行情/财务数据来自腾讯自选股接口。
- 选股规则不以历史收益率为优化目标，参数选择基于覆盖率、名单规模和结构指标。
- 财务数据按 `InfoPublDate <= 基准日` 过滤，避免未来函数。
- 生成物和本地缓存不提交；需要复现时重新运行脚本。
